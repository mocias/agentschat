# 0.1.37 界面与加载优化

2026-10-29。针对宽屏输入区留白和权限字号不一致，以及历史较多时启动、切换等待的问题。

## 界面

- 输入区居中、最大宽度 1080px，统一圆角、边框、焦点状态和按钮尺寸；权限文字从实际 19px 修正为 12px。
- 输入框随草稿增长并在清空时收回；会话切换恢复原草稿及高度。
- 侧栏选中态改为浅色强调，消息圆角、标题与工具按钮层级统一，保留五套主题及四种原生会话布局。
- 长历史首次渲染最近 120 条，可逐页展开全部旧消息，展开保持阅读位置；底层日志、搜索和导出仍包含完整历史。

## 加载路径

- 历史记忆回填每 256 条分批写入、同步；实时消息仍逐条 durable append。去重、私聊参与者边界、失败后回放与断尾恢复不变。
- `/api/catalog?fast=1` 提供已保存目录及检测状态，不等待全机程序扫描。原完整目录接口保留。
- `/api/conversation?preview=1` 优先读取活动运行态；无运行态时以原引擎构造临时历史视图，执行相同公开记录/附件规则后释放。它不启动原生连接、不缓存未配置的运行态；首次发送仍执行正常发现、检查和运行态创建。
- 首屏并行读取目录、主题、导航和数据位置。首次 SSE 连接不再重复拉取目录，后端检测在历史显示后进行。
- 导航保存、审批读取与历史读取并行；递增请求序号防止 A → B → A 的迟到响应覆盖新视图。审批、pending 与 SSE 快照保留较新的事件状态。

## 测量

`node scripts/benchmark-loading.cjs` 使用隔离数据：4 个 Agent、1200 条历史、固定 900ms 检测延迟；不调用真实模型。以下均为 3 次的中位数，服务初始化不含 Electron/模块加载时间，历史首屏从浏览器导航计时，不等于云模型首字延迟。

| 指标 | 0.1.36 | 0.1.37 |
| --- | ---: | ---: |
| 历史回填及服务初始化 | 4308ms | 40ms |
| 历史首屏显示 | 1391ms | 143ms |
| 切换会话 | 79ms | 48ms |
| 首屏消息 DOM | 1200 | 120 |
| 历史回填 fsync | 4801 | 21 |
| 初始目录请求 | 2 | 1 |

基线：`output/loading-before-xJ4GR1/report.json`；最终：`output/loading-final-Cl8UzT/report.json`。实际 Windows 发现、无注入延迟的单次隔离检查首屏 291ms：`output/loading-native-final-oe01GQ/report.json`。时间随硬件、缓存、并发负载与数据量变化，不作为统一速度保证。

`BENCH_VERIFY=1` 另验证全部旧消息可展开、阅读锚点、草稿自动高度及恢复、A → B → A 迟到响应、导航/审批延迟时历史仍可用。`BENCH_NATIVE_DISCOVERY=1` 使用本机发现；`BENCH_REPEATS` / `BENCH_MESSAGES` 可调整测试规模。

## 验证与边界

- `npm test`：143/143。与多个浏览器/磁盘压力任务同时运行时曾出现 Windows 文件替换 EPERM 及派生 fixture 创建失败；相关文件单测及完整套件独立重跑均通过，未删测试或放宽断言。
- `scripts/check-ui-appearance.cjs`：五套主题、深浅色、1440/1000/720/390px、输入/发送/菜单、提及、历史及共享记忆。
- `scripts/check-agent-sessions-ui.cjs`：原生配置、一次性审批与会话隔离；`UI_PACKAGED=1` 在最终 EXE 验证四种布局及重启恢复，0 次模型请求。
- 最终 ASAR 59 个源码文件逐字节匹配，不含测试、输出、个人数据或运行时目录；增量包在隔离旧版文件上重建并核对全部 SHA-256，数据/工作区哨兵保留。
- 附加原生目录检查中，ZCode 返回 `-32000`“当前没有可用的模型供应商和模型”。同机升级前 0.1.36 也复现；ZCode 接入文件与旧版逐字节一致。本次不宣称当前桌面账号的真实云模型请求可用，不自动更换凭据或发送测试聊天。
